============================================================
1. OBJETIVO DE LA ACTIVIDAD
============================================================

El presente taller práctico evaluativo tiene como propósito medir
las habilidades conceptuales, matemáticas y de programación en el
marco del razonamiento bajo incertidumbre (Softcomputing) y los
Sistemas Basados en Conocimiento (SBC).

Los dos casos planteados representan problemas reales de ingeniería
que requieren un análisis analítico riguroso y una implementación de
software flexible.


============================================================
2. MODALIDAD DE TRABAJO
============================================================

- El taller debe desarrollarse en parejas.
- El grupo debe tener máximo 2 integrantes.


============================================================
3. DISTRIBUCIÓN DE LA EVALUACIÓN
============================================================

3.1. MEMORIAS DE CÁLCULO ESCRITAS (TEÓRICO)
PORCENTAJE 50%

Se evaluará

- Desarrollo matemático paso a paso.
- Justificación analítica de cada fórmula de membresía.
- Desfusificación mediante centroide yo máximos.
- Cálculo completo de la propagación de factores de certeza.


3.2. IMPLEMENTACIÓN COMPUTACIONAL
PORCENTAJE 35%

Se evaluará

- Código fuente funcional.
- Código estructurado.
- Código modular.
- Código parametrizable.
- Implementación de ambos casos.
- Capacidad de evaluar cualquier valor nítido ingresado
  durante la ejecución de manera interactiva.

LENGUAJES PERMITIDOS

- Python
- MATLAB


3.3. CALIDAD DEL REPORTE Y PRESENTACIÓN
PORCENTAJE 15%

Se evaluará

- Redacción técnica profesional.
- Orden.
- Claridad metodológica.
- Cumplimiento de las pautas de presentación.


============================================================
4. ENTREGABLES
============================================================

4.1. MEMORIAS DE CÁLCULO

Las memorias de cálculo teóricas deben entregarse en un documento
digital ordenado o en formato PDF.

El documento debe presentar de manera clara y paso a paso los
procedimientos matemáticos realizados para ambos casos.


4.2. SOFTWARE

El software debe subirse a Google Classroom en un archivo comprimido
con extensión .zip.

El archivo debe contener

- Scripts correspondientes a los dos casos.
- Archivos necesarios para ejecutar el programa.
- Un README con un instructivo simple de ejecución.


============================================================
5. CARACTERÍSTICAS DEL SOFTWARE
============================================================

El programa debe

- Resolver los dos casos planteados.
- Ser funcional.
- Estar estructurado.
- Ser modular.
- Ser parametrizable.
- Permitir ingresar valores nítidos durante la ejecución.
- Poder evaluar diferentes valores ingresados por el usuario de
  manera interactiva.

No se debe limitar el programa únicamente a los valores utilizados
en los ejemplos o cálculos manuales.

7. README
============================================================
